## [0.22.1] - 2026-11-24

### Added
- BSP-Core's player reset (`/bsp player reset`, in a BSP-Core newer than 1.22.0) reaches this mod on every server, which needs this jar on the servers: the player is asked to agree to the rules again (cleared for the network where the reset was typed, elsewhere this server's copy; either way only an agreement made before the reset). Chunk unloading forgets an admin's RESTORE NOW hold on them; their unloaded machines stay unloaded, and a second later each one's owner is found again: one that was theirs only through a claim given up in the reset is kept unloaded with no owner, listed in the CHUNKS tab, as if an admin had unloaded it. Kept: the first-join record (the public player counter and the welcome), bans, staff panel notes and tags, staff talks, the Action Log, totem steals, last seen, and who placed each machine. With an older BSP-Core nothing changes.

### Changed
- Built against BSP-Core 1.23.0, so the older BSP-Core jars are no longer needed to build it. It still runs with the BSP-Core versions it ran with before.

## [0.22.0] - 2026-11-24

Streamer Mode (SU-131 to SU-136). A change in the game only: servers need nothing new and the network protocol is still 11.

### Added
- Streamer Mode: a second, clean picture of the game for OBS, in a window titled "BSP Stream" (OBS: Window Capture, or macOS Screen Capture in window mode), while the player's own window shows everything. Its menu opens from the eye key in the top-right corner of the title screen and the pause screen (it steps past widgets and FancyMenu's elements) or `/streamer`: an on and off switch with its key (unbound until set in Controls › Key Binds › BSP-Server Utilities), the output (the stream window, or on 64-bit Windows Spout2: no window, the picture goes to OBS's Spout2 Capture source from Off-World-Live's plugin as "BSP Stream"; if Spout2 cannot start, the stream window opens instead and chat says why), the frame rate (Match, 60 or 30), a live preview of what OBS gets, and a tile per mod (Minecraft, JourneyMap, BSP-Teleport, BSP-Core, BSP Region Guard when installed, and Other mods) whose page has a HIDDEN or SHOWN switch per item, HIDE ALL and SHOW ALL. Every HUD part a mod registers with Forge is listed; menus are hidden whole (the stream shows a "Menu hidden" card), and "Other mods' menus" hides every menu that is not Minecraft's own. Minecraft's page has "Chat: lines with coordinates": the stream leaves out each chat message that holds a position (whole, however it wraps; "100, 64, -200", "x: 1, z: 2" or "100 64 -200"), and what the player types when it holds one. JourneyMap's page also has "Minimap coordinates": the minimap stays in the stream and only its lines that hold coordinates (the location and region lines) are left out. Hidden at first: the F3 screen, chat lines with coordinates, JourneyMap's minimap, its coordinate lines, waypoint markers and menus, BSP-Teleport's coordinates (its whole band and portal screen with a BSP-Teleport before 3.9.2; from 3.9.2 BSP-Teleport hides only the numbers itself, the portal chooser's too, through the new `api.StreamerMode.hidesNow`, docs/API.md), BSP-Core's sentinel strip, recall card and Team screen, Region Guard's Land Office and region screens, and the admin screens of this mod, BSP-Teleport and BSP-Core and BSP-Core's Accelerator screen (they show positions); defaults added by a later version are applied once to existing players. While chat or its coordinates are hidden, the stream also leaves out command suggestions (Minecraft offers the block you look at), any command being typed, and chat's hover text. F1 hides the HUD in the stream as in the game. The choices are kept in `[streamer]` of `config/bsp_server_utilities-client.toml`. The jar carries Spout's `SpoutLibrary.dll` (Spout SDK 2.007.018, 64-bit, BSD-2-Clause, unchanged, with its licence in `natives/windows-x64/`); it is copied to `bsp_server_utilities/natives/` in the game folder and loaded only when Spout2 is used on Windows. `/streamer on` and `off` switch it directly; closing the stream window turns it off.

## [0.21.0] - 2026-11-22

Multiplayer's servers as a grid. A change in the game only: servers need nothing new and the network protocol is still 11.

### Added
- Multiplayer's server list shows the servers as a grid in place of Minecraft's list: the BSP server in a card across the whole width on top (its icon, name, message of the day, player count and ping), then every other saved server as a square card (its icon, name, the first line of its message, player count and ping) and every LAN game as a square (LAN World, the world's name and its address), in the list's own order, then "Scanning for games on your local network". Tags mark incompatible versions, LAN games, the Builtin Servers badge and the selected card; hovering the ping bars, the player count or the badge shows what Minecraft (or Builtin Servers) shows there. Click to select, double-click or Enter to join; hovering a server shows Minecraft's icon actions as keys (< moves it one place earlier in the list, JOIN joins it, > one place later); the arrows move across the grid (up from the first row to the BSP card); Shift and an arrow moves a server in the list; the scroll position is kept when the screen comes back from Edit, Add or Delete; the mouse wheel and the scrollbar scroll; Join Server, Direct Connection, Add Server, Edit, Delete, Refresh and Back work exactly as before. Client settings in `[menus]` of `config/bsp_server_utilities-client.toml`: `serverGrid` turns it off and gives Minecraft's own list; `featuredServer` (`buildsecureprotect.com`) names the server on top: a host, or a domain its hosts end with.

### Changed
- The Select World grid and the Multiplayer grid share one way of taking over Minecraft's list (`client/GriddedLists`); the mixin that stops the replaced list drawing its rows is `GriddedListMixin` (was `WorldListGridMixin`).

## [0.17.0] - 2026-11-22

Private staff messages: staff write privately to a player in game or from the staff web panel, the player answers in their own window. **The network protocol is 10: players need the new modpack**, and every server needs 0.17.0. Install with staff panel 0.6.0 and its two database grants (`docs/STAFF_PANEL_SETUP.md`, Running it › Updating to panel 0.6.0).

### Added
- Private staff messages, the record: one conversation per player that every staff member shares, written by staff and answered by the player, kept in two new shared tables `bsp_su_talks` and `bsp_su_talk_lines` (or in the world on a server without shared storage). Only staff write to players and never to other staff; lines are plain text of up to 256 characters, 30 a minute for each staff member and 10 for a player; any staff member ends a conversation and the next staff line starts a new one. Lines are kept 90 days; a conversation left with no line ends itself. The Action Log records each conversation's start and end. Each line carries a signed copy for the staff web panel.
- Private staff messages reach people on every server: when staff write, the player gets a popup (who wrote, never the words) and a chat line with [OPEN], and their MESSAGE STAFF key appears and flashes until they answer; a player who was offline gets the popup a few seconds after they next log on (after the rules), once, on whichever server. Every staff member online hears each answer, and the other staff hear when someone ends a conversation. The network protocol is 10: players need the new modpack.
- Private staff messages, the commands: `/su msg <player> <text>` writes to a player online or not (found anywhere on the network, or among everyone who ever joined) and says where they are; `/su talk <player>` opens the staff window with their conversations of the last 90 days; `/su talks` lists the open conversations, those waiting on staff first; players use `/su talk` for their own conversation, so `/su` is open to every player (each part keeps its own permission). Lines arrive live in every open window.
- Private staff messages, the screens: the MESSAGE STAFF key in the inventory (right of SUPPORT BSP, clear of every other button, the recipe book, JEI and EMI; flashing red while a staff line waits; a client setting `messageButton` hides it), the STAFF MESSAGE popup (shown at a quiet moment: no other screen open and not hurt in the last 10 seconds), and the private window for the player and for staff (speech bubbles, live lines, a 256-character box, END CONVERSATION for staff with SURE? within 3 seconds).
- Private staff messages from the staff web panel, the game server's part: the signed actions `talk_send` and `talk_end` (every panel rank, the same rules as in game), each line told to the panel live (kind `talk`, its signed copy), and `talk` in the snapshot.

## [0.11.1] - 2026-11-17

The AFK and macro kick, checked against its design. Players need 0.11.1 too only for the card fixes; the network protocol is still 7, so 0.11.0 clients still join.

### Changed
- AFK macros: a pattern of head turns needs only 2 inputs in the 10 minutes (was 20), so a mouse jiggle once a minute, or every few minutes, is caught too; a pattern with clicks, uses, container opens or other actions needs 6 (about one every 100 seconds or faster), so a still player checking a furnace or reading a book every few minutes stays active. "macro?" and what was seen show only once the pattern has kept an input from counting, so a player who looked around twice and walked away is shown as idle, not as a macro.
- AFK macros: steering counts towards a macro only at one spot (a boat against a wall), never on a long ride with the mouse still.
- A presence check shows the HUD again if it was hidden with F1, so the card and the red line are seen.
- The AFK tab shows a staff member's check countdown in gold: staff are checked but never kicked.
- When the proxy does not take a kicked player off the network within 3 seconds, the server's console says so (BSP-Velocity Additions' network kick missing or off) as this server kicks them itself.

### Fixed
- AFK: a machine's fake player (Create's deployer reports its owner's UUID) no longer keeps its owner active, ends their presence check or brings their unloaded chunks back; only what the player does counts.
- AFK macros: different chat lines, and the same command with different words, are different inputs, so a player chatting at one spot is not taken for a macro; the same line again and again still is.
- AFK: a presence check under way ends when the rules popup holds the player, and after they agree a new check gives them the full 2 minutes, instead of kicking them at once.
- AFK: after the hour's clearance, or the macros switch off and on, "what was seen" counts the minutes from when the pattern came back, not from before.
- `/afk` typed just after moving the mouse is no longer undone a second later.
- The presence check's card goes when the player joins or moves to another server of the network; it is placed again after the window or GUI scale changes, so it stays off the hotbar and crosshair; every click on it (any button, anywhere on the card) stays on it, before other mods' lists such as JEI; the release and drag of a button it took stay on it too, so a stack carried in a chest screen is never dropped or placed by a click on the card; it is drawn higher, above anything a screen draws before it.
- The staff card reads "or you will stay AFK", as the chat line does.
- An unanswered check after the rules popup logs the idle time from the player's last input, not from the rules.
- The AFK tab's data cuts a server id over 64 characters and a description over 512, instead of failing to send.
- The AFK and chunk settings written as the network's first copy at start are read on the server thread.

## [0.11.0] - 2026-11-12

### Added
- Every server's Compact Machines rooms are shared through the network database (`<prefix>cm_rooms`, `<prefix>cm_servers`, notice `cm_rooms`; docs/API.md), so a player's rooms can count across the network. New server config section `[rooms]`: `limit` (0: no limit, only counted), `scope` (`network` or `server`), `exemptGroup`, `graceDays` (7).
- The room limit: with `[rooms] limit` set, a player at or over it cannot make a new Compact Machines room (the Personal Shrinking Device's first click on a new machine is refused, with a line saying how many to give back); entering existing rooms always works, and an owner over the limit is reminded in chat at most once a minute. Operators and `exemptGroup` are never limited.
- A Compact Machines room whose machine item is destroyed (burnt, blown up, on a cactus, crushed, into the void, despawned or cleared from the ground) stops counting at once and waits `graceDays` (7) before it is cleared, unless a machine bound to it is placed again or another placed machine is still bound to it. Only the room's own server acts (BSP-InventorySync's home mark; other servers send it the loss). Its owner is told at once when on that server, otherwise at their next login anywhere. When the grace ends the room is cleared: players inside are sent to their respawn point, everything inside is removed (nothing drops), and the room's place is kept for nobody so it is never reused; the rooms of machines that stood inside go into grace themselves; a machine still bound to a cleared room works as a new one.
- `/su rooms`, for every player where Compact Machines runs: their rooms on every server as tiles drawn to each room's size, the count against the limit, rooms waiting to be cleared with how long is left, and GIVE BACK (with SURE?) for an empty room on this server with no machine placed. The guide is the admin panel itself: the tab row shows the page's tab (clicking it does nothing during the guide), a progress bar and a violet strip give the step and what the feature does, the body is that feature's tab (the Client check page opens on its RULES half), and BACK, TURN OFF FEATURE (or TURN ON FEATURE), SETUP LATER and NEXT replace the tab's footer; turning off the action log asks a second time under a red warning. Welcome (this server's name, the storage in use, the servers heard from), Display panels and Finish (every page set up, off or later; DONE) are pages of their own. Closing the guide part way leaves the rest for later. SETUP GUIDE on the RULES tab reopens it.
- Off switches for every feature, saved for the network: the rules popup (nobody asked or held; the config file's switch still works too), the action log (nothing recorded), despawn times (items go back to vanilla's five minutes), the client check (nobody asked or refused), staff online (panels and boards show nobody; no presence sent) and display panels (existing panels go dark; new ones cannot be placed); AFK and chunk unloading use their own switches.

### Changed
- The mod's network protocol is now version 2: clients and servers must both have this version to connect.
- Shared storage loads its MySQL driver itself before connecting (the server's own when it has one, else the copy in BSP-Core's full jar), so on plain Forge it no longer depends on BSP-Core reaching the database first. Without any driver the log says to install BSP-Core's full jar (not the -slim one).

## [0.1.0] - 2026-10-20

### Added
- The AFK tab of the admin panel (`/su`): AFK DETECTION (mark idle players AFK, AFK after 1 to 60 minutes, what counts as active) and KICKING (kick players AFK too long, after 5 to 240 minutes AFK in steps of 5, the kick message up to 160 characters), saved for every server; beside them everyone AFK now on any server with how long and where, a red "kicked in …" for anyone within five minutes of a kick, and staff away by `/su away`. The list is fetched again every five seconds while the tab is open.
- AFK detection, server side: a player who neither turns their head nor does anything the server sees (chat, commands, breaking, placing, using, attacking, clicking in a container, dropping, steering a vehicle) for 5 minutes is AFK and told so; being carried by water or a minecart does not count as active, and a player at the rules popup is never idle. Their next action brings them back. `/afk` marks a player AFK at once. Staff who are AFK show as away on the staff panels and boards until they act (a typed `/su away` stays). With kicking on (off by default), a player AFK for 30 minutes is warned a minute before and then sent off with the admin's message; staff and operators are never kicked. The settings are one set for the network; `/su status` shows them. Every server tells the others who is AFK on it.
- `/actionlog` for every player: a read-only teal screen with the newest 100 entries of the action log, coordinates hidden (how long ago, who in their role's colour, what, the server; hover a cut line for all of it; the wheel scrolls; CLOSE or Escape), following the log while open. With BSP-Core, ACTION LOG is also a board for its Score Screens (who in their role's colour, what, how long ago).
- The LOG tab of the admin panel (`/su`): WHAT IS LOGGED lists every command the server knows and every command seen in the log, each with its switch, and a box to find one; private messages are listed as never logged and have no switch. Turning a switch off or on takes effect on every server and shows as an entry. Beside it the newest 300 entries in full text (how long ago, who in their role's colour, what, the server; hovering a cut line shows all of it), filtered by server and by kind from the footer, and kept current while the tab is open.
- The action log on Display Panels: a panel in Action log mode shows ACTION LOG, where the entries come from and how long they are kept, then the newest entries as a table: how long ago, who in their role's colour, what (coordinates hidden, since everyone reads panels) and the server. Its settings choose every server or this one, which kinds (commands, creative items, game modes, gives, switches) and 6, 8 or 12 lines; the face fills the panel at any size. Every player's copy of the newest 200 entries is kept current (at most once a second) and sent at login.
- The action log, server side: every command run by staff, operators, the console ("Console") and RCON is recorded with who, their role, the server and when (private messages never; command blocks and other players are not logged); items staff take from the creative menu (counted per item over five seconds, so moving items around is not logged), gives, game-mode changes, and BSP-Core's admin kit gives. Admins can switch single commands off (`ActionLog.setSwitch`; the LOG tab follows), and every switch change is itself an entry. Entries are shared by the network and deleted after `log.keepDays` (7); nobody can edit or delete one in game. Players will read entries with coordinates hidden.
- Staff online on panels and in the admin panel: a Display Panel in Staff online mode shows STAFF ONLINE and the count, a column per role in its colour, and each person with a dot (green online, amber away, grey offline) and their server, "away" or how long ago; its settings choose online and offline or online only, and which roles. The admin panel's STAFF tab edits the staff groups for the network (a LuckPerms group, the label and colour panels show, the order; the operators switch) and lists everyone with their role and where they are. With BSP-Core, STAFF ONLINE is also a board for its Score Screens. Every player's copy of the roster is kept current (at most once a second).
- Staff online, server side: the staff groups (LuckPerms group, label, colour, in order) and whether operators count are kept for the whole network, filled from `staff.groups` the first time; each server tells the others which staff are online (on every join, leave and away change, and every 30 seconds; a server's list counts for 90 seconds); `/su away` marks a staff member away until they use it again or leave (staff who are not admins may use it); when staff leave a server, when and where is recorded for the network; the roster lists everyone in a staff group per LuckPerms (offline too) and operators who have played here, online ones with their server.
- Pictures on Display Panels: the settings screen's IMAGE mode shows the face with the picture as players see it and lets an admin choose a web address or a file from the server's images folder (listed with sizes), the fit (fit inside, fill and crop, stretch), REFRESH NOW and a refresh timer (off, 5, 15 or 60 minutes); the footer says what the last load brought or why it failed. The picture is drawn on the face at full brightness across the whole panel, inside the bezel, over the background (or the wall when clear).
- Pictures for Display Panels, server side: a panel in Image mode gets its picture from a web address (http or https, up to `images.maxDownloadKB`, answering within `images.timeoutSeconds`) or from a file in `config/bsp_server_utilities/images/` (PNG, JPEG, the first frame of a GIF). The server reads it, scales it down to what the panel can show (`images.pixelsPerBlock`, 128), keeps it as a PNG and sends it to players in pieces when their game asks; players never contact the address. A picture is loaded when it is saved, by REFRESH NOW, on a timer (5, 15 or 60 minutes) for web pictures, and again after a restart when a player needs it. What came of the last load (the size and format, or why it failed) is kept on the panel.
- Text on Display Panels: an admin right-clicks a panel to open its settings, with the face as players will see it at the top (click a line to pick it) and the picked line's text (up to 80 characters, `&` codes for colours and styles inside a line), size (S, M, L, XL, a share of the panel's height, so a line keeps its proportion on any size of panel), colour (the 16 chat colours or a #RRGGBB value), alignment and bold; up to 16 lines; a dark background or clear. Nothing changes in the world until SAVE; CLOSE and Escape leave the panel as it was. The face is drawn across the whole joined panel at full brightness; a line too wide is shrunk to fit and too many lines are scaled down together.
- The Display Panel block (Functional Blocks tab; no recipe): a thin wall panel 3 pixels deep with a black face. Panels of the same facing side by side and above each other join into one panel, the largest full rectangle up to 8 x 6 counted from the bottom-left block; a slim dark bezel runs round the outside of the joined panel only, with a small teal light in its bottom-right corner. Every block keeps a copy of the panel's settings, so a panel keeps them when blocks are added on its left or bottom or its bottom-left block is broken, and the newer settings win when two panels join. Only admins can place it, set it up and break it (an admin in survival gets it back); pistons and explosions leave it alone.
- The admin panel, `/serverutils` (or `/su`) on its own, for operators and BSP-Core admins, with the RULES tab: POPUP TEXT (the heading, the intro line and the message LEAVE SERVER shows), the rules in order and + ADD RULE on the left; on the right the picked row's boxes with counters against the limits, UP, DOWN and DELETE (SURE?). The footer shows the version and how many players on the network agreed to it, PREVIEW (the popup exactly as players see it; nothing is sent) and ASK EVERYONE AGAIN (SURE?). What is typed is saved a second after typing stops, when another row is picked, and when the panel closes.
- The rules popup screen: one teal panel with the heading, the intro and every rule in a scrolling list (number, bold title, text) with a tick box on the right of each; a click anywhere on a rule's row ticks it; AGREE stays dim with "Tick every rule to agree" until every box is ticked; LEAVE SERVER at the bottom left. Escape does nothing while the player must answer, and the popup opens again by itself if another screen replaces it. `/rules` opens the same panel read-only with the date the player agreed and CLOSE. Key presses stay inside the mod's screens.
- The rules popup, server side: one set of rules for the network (a heading, an intro line, the message LEAVE SERVER shows, and up to 20 rules, each a title of up to 48 characters with optional text of up to 400). A player who has not agreed to the current version is held once they have settled in (after BSP-InventorySync has restored their inventory, or 2 seconds after login): kept in place, unable to build, use, attack, pick up or drop items, open containers, chat or run commands other than `/rules`, and unhurt. AGREE is taken only with every rule ticked on the rules they were shown; LEAVE SERVER disconnects with the admin's message. Agreements count for the whole network. Asking everyone again raises the version and asks every player online at once.
- `/rules` for everyone (a read-only copy; for a held player, the popup again) and `/su rules list | add <title> [text] | remove <n> | status | reset <player> | askagain` for admins.

- Shared storage for the network: the server config (`serverconfig/bsp_server_utilities-server.toml`) reads BSP-Core's database, Redis and server name by default (`storage.mode = "auto"`, `useBspCoreDatabase`, `useBspCoreRedis`), with this mod's own tables (`bsp_su_` prefix) and its own small Redis client; notices between servers through Redis and a notice table, notices older than a day deleted hourly.

- Editing rights: operators (level 2) and BSP-Core admins.
- `/serverutils status` (short form `/su status`): where records are kept, this server's name, LuckPerms, BSP-Core and the staff groups.
- The project: Forge 1.20.1 mod `bsp_server_utilities`, BSP-Core 1.4.0 as an optional dependency, the LuckPerms API for compiling, the GameTest setup with an empty test structure, and the language file generator.
