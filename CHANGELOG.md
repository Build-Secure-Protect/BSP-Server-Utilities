# Changelog

All notable changes to this project are documented in this file. The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

## [0.5.0] - 2026-10-25

### Added
- The player counter, server side: every player who joins any server of the network for the first time is counted once, by UUID, from the day the counter starts (players from before are not counted; players the client check refuses never joined). With shared storage the network keeps one list, a row per player inserted once, so two servers never count the same player twice; without it each server keeps its own. The number shown is the real list plus an adjustment: `/su players` (the number, the real count and the adjustment, new today and in the last seven days, the newest), `/su players set <n>`, `add <n>` (a negative number takes away; never below 0), `reset` (0 from now) and `true` (back to the real count); each change, and a change of the title or the welcome words, is written to the Action Log under who made it. A new player is welcomed in gold in words admins type, with `{name}` and `{number}` filled in (up to 160 characters, starting "Welcome {name}, player number {number} on BSP!"), on every server of the network: as typed on the server joined, after that server's name in grey ("[BSP-Spawn] Welcome ...") on the others, with the number as shown. Every player's copy (title, number, new today, new this week, newest and how long ago) is kept current. A Players line in `/su status`.
- The setup guide's Player counter page, after Display panels (the guide has eleven pages): the number shown and the real count, SET and ADD with a typed number, RESET TO 0 (a second click to confirm) and REAL COUNT, the title (up to 32 characters, "Players of BSP" to start) and the welcome line's words with the line as it will read; TURN OFF FEATURE stops the counting and the welcome, and the board and panels show nothing. Existing servers are asked about this page at an admin's next join.
- The PLAYERS board for BSP-Core's Score Screens: the counter's title, then "Have played BSP" with the number in gold, "New today", "New this week" and "Newest" with the name and how long ago.
- The Player count mode on Display Panels, the fifth mode: the title in teal, the number large in gold, "players have joined the network" under it, and the new counts ("12 new today · 58 this week") when the panel's tick is on. Each panel can type its own title (up to 32 characters); empty, it shows the counter's.

### Changed
- The mod's network protocol is now version 3: clients and servers must both have this version to connect.
- Built against BSP-Core 1.5.0 (any BSP-Core from 1.4.0 still works, and BSP-Core stays optional).

## [0.4.2] - 2026-10-25

### Fixed
- On a network with shared storage, SETUP NOW (and `/su setup`) opened the plain admin panel instead of the setup guide, so there was no NEXT, SETUP LATER or DONE: the panel waits for the database's count of players who agreed to the rules, and the guide's data reached the client before the panel and was dropped. The guide's data now follows the panel, and a client that still gets it early keeps it until the panel opens.

## [0.4.1] - 2026-10-24

### Fixed
- The setup card in the top right corner was hidden behind JourneyMap's minimap (and could be behind any HUD drawn at the end of the frame). It is now drawn when Forge has finished the whole HUD, over everything else, so it is always in sight and, with chat open, clickable.

## [0.4.0] - 2026-10-23

### Added
- The client check, the client's report: every client joining a server answers, inside Forge's login handshake, with what it has: every mod with its version and the SHA-1 of its file, the resource packs switched on with the SHA-1 of each pack file, the shader pack Oculus has chosen and whether shaders are on, the brightness, and the stone test (common stone-type blocks such as stone, deepslate, dirt, gravel and netherrack must still have all six faces, draw as solid blocks and not be largely see-through; the first that fails is reported with the pack that changed it). The server holds the login until the answer has been judged, so a refused player never enters the world; a client that does not answer in 20 seconds is turned away. The mods' files are read once in the background when the game starts; a resource reload in game, or the brightness crossing the slider's top, sends the report again. Singleplayer and LAN games are never asked.
- The client check, server side: the rules are a block list (a word anywhere in a mod's id or name, a pack's name or the shader's name; an exact mod id; a pack by its fingerprint, whatever it is called), names allowed anyway, exempt players and the refusal message (starting "You can't join with: <list>. Remove them and join again; ask staff if you think this is wrong."; the starting words are xray, x-ray, freecam, baritone, wurst and meteor). A player with something blocked, or a failed stone test, is refused before entering the world with the list of what to remove; switching on a blocked pack in game kicks with the same message. Blocking something a player online already has flags them and kicks nobody; they are refused at their next join. Admins see, without anyone being refused: mods not in the trusted setup, pack mods whose file differs from it, packs not in it, a brightness past the slider's top (the player is told once per join that staff can see it) and mods Forge listed that the report left out. The trusted setup is an admin's own client, taken in one press; it is written to `config/bsp_server_utilities/trusted_setup.json`, and a server reads a newer copy of that file at start-up or on `/su clientcheck reload`. The rules and setup are the network's, or a server's own when it switches (starting as a copy). Every server tells the others about its players' reports; a staff kick with a typed reason ("Removed by staff") reaches the server the player is on; refusals and kicks go to the Action Log (a new kind, Client check, seen by staff in the LOG tab only: players' copies on panels, `/actionlog` and the board leave them out) and to the list of today's refusals. `/su client <player>`, `/su clientcheck export | reload`, and a Client check line in `/su status`.
- The CLIENTS tab of the admin panel (`/su`), the seventh tab (the tab keys are narrower so seven fit beside the title): PLAYERS lists everyone on the network with a report, flagged players first with their flag count, "blocked" for what would now refuse them, "exempt", then today's refusals; picking a player shows their flags (blocked since they joined, brightness, mods not trusted, files that differ, packs not trusted, mods left out of the report, the stone test, the shader), their mods or packs with the unusual ones first, BLOCK on each line, and KICK with a typed reason (each a second click to confirm). RULES: Network rules or Its own rules; the trusted setup with TRUST MY SETUP (a second click) and EXPORT; the refusal message (saved a second after typing stops); the block list (a word or a mod id), the names allowed anyway and the exempt players (a name, then a note), each with + add and ×.
- The setup guide, server side: a few seconds after an operator or BSP-Core admin joins (once the rules popup and their inventory are done), they are offered the setup while any page is not finished, as a clickable line in chat ([Setup now] [Later] [Ignore setup]; the card in the corner comes with the screens). The pages are Welcome, Staff groups, Rules, Action log, AFK, Chunk unloading, Despawn times, Client check and Display panels: each is set up (NEXT, or a change in its own tab), left for later (the admin is reminded at their next join; closing the guide part way leaves the rest for later) or turned off. Progress, the switches and who chose to ignore the guide are kept for the network; the Welcome page (this server's name, which is written to the config file and used after a restart) is each server's own, so a server added later asks only about that. `/su setup [now | later | ignore]` and a Setup guide line in `/su status`. Existing servers start with every page not set up.
- The setup guide's screens: the card in the top right corner (CONFIGURE SERVER UTILITIES, or SERVER UTILITIES: n LEFT with the pages not finished in gold) does not stop the game; its keys (SETUP NOW or CONTINUE SETUP, LATER, IGNORE SETUP, × for later) can be clicked whenever chat is open, and it stays until a choice is made, hidden while another screen is open. The guide is the admin panel itself: the tab row shows the page's tab (clicking it does nothing during the guide), a progress bar and a violet strip give the step and what the feature does, the body is that feature's tab (the Client check page opens on its RULES half), and BACK, TURN OFF FEATURE (or TURN ON FEATURE), SETUP LATER and NEXT replace the tab's footer; turning off the action log asks a second time under a red warning. Welcome (this server's name, the storage in use, the servers heard from), Display panels and Finish (every page set up, off or later; DONE) are pages of their own. Closing the guide part way leaves the rest for later. SETUP GUIDE on the RULES tab reopens it.
- Off switches for every feature, saved for the network: the rules popup (nobody asked or held; the config file's switch still works too), the action log (nothing recorded), despawn times (items go back to vanilla's five minutes), the client check (nobody asked or refused), staff online (panels and boards show nobody; no presence sent) and display panels (existing panels go dark; new ones cannot be placed); AFK and chunk unloading use their own switches.

### Changed
- The mod's network protocol is now version 2: clients and servers must both have this version to connect.
- Shared storage loads its MySQL driver itself before connecting (the server's own when it has one, else the copy in BSP-Core's full jar), so on plain Forge it no longer depends on BSP-Core reaching the database first. Without any driver the log says to install BSP-Core's full jar (not the -slim one).

## [0.3.0] - 2026-10-22

### Added
- The DROPS tab of the admin panel (`/su`): DESPAWN (count time while nobody is near, ITEMS and DEATH DROPS 1 to 60 minutes, XP orbs following items) and CLEAR ITEMS NOW (this server, all servers or one by name; a second click to confirm); the exceptions on the right with + add an item (a search over every item by name or id, the picked item's time 1 to 120 minutes or NEVER) and × to remove; the footer counts what went in the last hour. The title is drawn smaller when six tabs need the room.
- Despawn times for dropped items, server side: items and experience orbs on the ground last 5 minutes of the server's running time, counted whether or not anyone is near, so piles in places nobody visits go as soon as their chunk loads and chunks held without entity ticking stop collecting them; a player's death drops last 15 minutes; orbs follow the items' time; per-item exceptions (1 to 120 minutes, or never). Items whose mod gives them a lifespan of their own, and BSP-Core's items, are never touched. Nothing counts per item: each is stamped once when it drops and checked once every 5 seconds (5,000 items take under 2 ms). The settings are one set for the network; `/su status` shows them and how many items and orbs were removed in the last hour.
- `/su clearitems here | all | <server>` (operators and BSP-Core admins): the chosen servers warn their players 60 and 30 seconds before, then remove every dropped item and orb (never exceptions, mod-timed and BSP-Core items kept); items in chunks not loaded at the time go when their chunk next loads; each server reports its count to the admin. A second clear during a countdown starts it again.

## [0.2.0] - 2026-10-21

### Added
- The CHUNKS tab of the admin panel (`/su`): UNLOADING (on or off, after 1 to 60 minutes away), the mods never unloaded as chips (BSP-Core always), the players always loaded (+ add a player by name); every player whose machines hold chunks on this server with where they are and how many chunks are loaded and unloaded; machines whose owner could not be found, with UNLOAD and RESTORE. Picking a player shows their machines (mod, place, chunks) with RESTORE NOW and UNLOAD NOW (a second click to confirm). The tab keys are a little narrower so five fit beside the title.
- Chunk unloading, server side: once a minute each server looks at the chunks other mods keep loaded through Forge (RFTools Builder, Mekanism's Anchor upgrade, AE2's spatial anchor, Flux Networks, Railcraft's worldspikes and the like) and finds whose machine holds each: the owner the machine saves itself, else who placed it (recorded from now on), else the owner of the BSP-Region Guard claim it stands in. When that player has been away from this server for 5 minutes (moving to another server counts), the machine's chunks are unloaded; when they join again they load again, a few at a time, if the machine is still there, and the player is told. BSP-Core's totem and projector chunks are never touched, nor temporary loads (teleports, trains, world generation), `/forceload` or plugin chunks. Admins can exempt mods, mark players always loaded, give a player's chunks back early, unload them at once, and unload machines whose owner could not be found. The settings are one set for the network; `/su status` shows them and how many tickets are unloaded.

## [0.1.0] - 2026-10-20

### Added
- The AFK tab of the admin panel (`/su`): AFK DETECTION (mark idle players AFK, AFK after 1 to 60 minutes, what counts as active) and KICKING (kick players AFK too long, after 5 to 240 minutes AFK in steps of 5, the kick message up to 160 characters), saved for every server; beside them everyone AFK now on any server with how long and where, a red "kicked in …" for anyone within five minutes of a kick, and staff away by `/su away`. The list is fetched again every five seconds while the tab is open.
- AFK detection, server side: a player who neither turns their head nor does anything the server sees (chat, commands, breaking, placing, using, attacking, clicking in a container, dropping, steering a vehicle) for 5 minutes is AFK and told so; being carried by water or a minecart does not count as active, and a player at the rules popup is never idle. Their next action brings them back. `/afk` marks a player AFK at once. Staff who are AFK show as away on the staff panels and boards until they act (a typed `/su away` stays). With kicking on (off by default), a player AFK for 30 minutes is warned a minute before and then sent off with the admin's message; staff and operators are never kicked. The settings are one set for the network; `/su status` shows them. Every server tells the others who is AFK on it.
- `/actionlog` for every player: a read-only teal screen with the newest 100 entries of the action log, coordinates hidden (how long ago, who in their role's colour, what, the server; hover a cut line for all of it; the wheel scrolls; CLOSE or Escape), following the log while open. With BSP-Core, ACTION LOG is also a board for its Score Screens (who in their role's colour, what, how long ago).
- The LOG tab of the admin panel (`/su`): WHAT IS LOGGED lists every command the server knows and every command seen in the log, each with its switch, and a box to find one; private messages are listed as never logged and have no switch. Turning a switch off or on takes effect on every server and shows as an entry. Beside it the newest 300 entries in full text (how long ago, who in their role's colour, what, the server; hovering a cut line shows all of it), filtered by server and by kind from the footer, and kept current while the tab is open.
- The action log on Display Panels: a panel in Action log mode shows ACTION LOG, where the entries come from and how long they are kept, then the newest entries as a table: how long ago, who in their role's colour, what (coordinates hidden, since everyone reads panels) and the server. Its settings choose every server or this one, which kinds (commands, creative items, game modes, gives, switches) and 6, 8 or 12 lines; the face fills the panel at any size. Every player's copy of the newest 200 entries is kept current (at most once a second) and sent at login.
- The action log, server side: every command run by staff, operators, the console ("Console") and RCON is recorded with who, their role, the server and when (private messages never; command blocks and other players are not logged); items staff take from the creative menu (counted per item over five seconds, so moving items around is not logged), gives, game-mode changes, and BSP-Core's admin kit gives. Admins can switch single commands off (`ActionLog.setSwitch`; the LOG tab follows), and every switch change is itself an entry. Entries are shared by the network and deleted after `log.keepDays` (7); nobody can edit or delete one in game. Players will read entries with coordinates hidden.
- Staff online on panels and in the admin panel: a Display Panel in Staff online mode shows STAFF ONLINE and the count, a column per role in its colour, and each person with a dot (green online, amber away, grey offline) and their server, "away" or how long ago; its settings choose online and offline or online only, and which roles. The admin panel's STAFF tab edits the staff groups for the network (a LuckPerms group, the label and colour panels show, the order; the operators switch) and lists everyone with their role and where they are. With BSP-Core, STAFF ONLINE is also a board for its Score Screens. Every player's copy of the roster is kept current (at most once a second).
- Staff online, server side: the staff groups (LuckPerms group, label, colour, in order) and whether operators count are kept for the whole network, filled from `staff.groups` the first time; each server tells the others which staff are online (on every join, leave and away change, and every 30 seconds; a server's list counts for 90 seconds); `/su away` marks a staff member away until they use it again or leave (staff who are not admins may use it); when staff leave a server, when and where is recorded for the network; the roster lists everyone in a staff group per LuckPerms (offline too) and operators who have played here, online ones with their server.
- Pictures on Display Panels: the settings screen's IMAGE mode shows the face with the picture as players see it and lets an admin choose a web address or a file from the server's images folder (listed with sizes), the fit (fit inside, fill and crop, stretch), REFRESH NOW and a refresh timer (off, 5, 15 or 60 minutes); the footer says what the last load brought or why it failed. The picture is drawn on the face at full brightness across the whole panel, inside the bezel, over the background (or the wall when clear).
- Pictures for Display Panels, server side: a panel in Image mode gets its picture from a web address (http or https, up to `images.maxDownloadKB`, answering within `images.timeoutSeconds`) or from a file in `config/bsp_server_utilities/images/` (PNG, JPEG, the first frame of a GIF). The server reads it, scales it down to what the panel can show (`images.pixelsPerBlock`, 128), keeps it as a PNG and sends it to players in pieces when their game asks; players never contact the address. A picture is loaded when it is saved, by REFRESH NOW, on a timer (5, 15 or 60 minutes) for web pictures, and again after a restart when a player needs it. What came of the last load (the size and format, or why it failed) is kept on the panel.
- Text on Display Panels: an admin right-clicks a panel to open its settings, with the face as players will see it at the top (click a line to pick it) and the picked line's text (up to 80 characters, `&` codes for colours and styles inside a line), size (S, M, L, XL, a share of the panel's height, so a line keeps its proportion on any size of panel), colour (the 16 chat colours or a #RRGGBB value), alignment and bold; up to 16 lines; a dark background or clear. Nothing changes in the world until SAVE; CLOSE and Escape leave the panel as it was. The face is drawn across the whole joined panel at full brightness; a line too wide is shrunk to fit and too many lines are scaled down together.
- The Display Panel block (Functional Blocks tab; no recipe): a thin wall panel 3 pixels deep with a black face. Panels of the same facing side by side and above each other join into one panel, the largest full rectangle up to 8 x 6 counted from the bottom-left block; a slim dark bezel runs round the outside of the joined panel only, with a small teal light in its bottom-right corner. Every block keeps a copy of the panel's settings, so a panel keeps them when blocks are added on its left or bottom or its bottom-left block is broken, and the newer settings win when two panels join. Only admins can place it, set it up and break it (an admin in survival gets it back); pistons and explosions leave it alone.
- The admin panel, `/serverutils` (or `/su`) on its own, for operators and BSP-Core admins, with the RULES tab: POPUP TEXT (the heading, the intro line and the message LEAVE SERVER shows), the rules in order and + ADD RULE on the left; on the right the picked row's boxes with counters against the limits, UP, DOWN and DELETE (SURE?). The footer shows the version and how many players on the network agreed to it, PREVIEW (the popup exactly as players see it; nothing is sent) and ASK EVERYONE AGAIN (SURE?). What is typed is saved a second after typing stops, when another row is picked, and when the panel closes.
- The rules popup screen: one teal panel with the heading, the intro and every rule in a scrolling list (number, bold title, text) with a tick box on the right of each; a click anywhere on a rule's row ticks it; AGREE stays dim with "Tick every rule to agree" until every box is ticked; LEAVE SERVER at the bottom left. Escape does nothing while the player must answer, and the popup opens again by itself if another screen replaces it. `/rules` opens the same panel read-only with the date the player agreed and CLOSE. Key presses stay inside the mod's screens.
- The rules popup, server side: one set of rules for the network (a heading, an intro line, the message LEAVE SERVER shows, and up to 20 rules, each a title of up to 48 characters with optional text of up to 400). A player who has not agreed to the current version is held once they have settled in (after BSP-InventorySync has restored their inventory, or 2 seconds after login): kept in place, unable to build, use, attack, pick up or drop items, open containers, chat or run commands other than `/rules`, and unhurt. AGREE is taken only with every rule ticked on the rules they were shown; LEAVE SERVER disconnects with the admin's message. Agreements count for the whole network. Asking everyone again raises the version and asks every player online at once.
- `/rules` for everyone (a read-only copy; for a held player, the popup again) and `/su rules list | add <title> [text] | remove <n> | status | reset <player> | askagain` for admins.
- Server config `[rules]`: `enabled`, `delayTicks` (40), `restoreTimeoutTicks` (400).
- Shared storage for the network: the server config (`serverconfig/bsp_server_utilities-server.toml`) reads BSP-Core's database, Redis and server name by default (`storage.mode = "auto"`, `useBspCoreDatabase`, `useBspCoreRedis`), with this mod's own tables (`bsp_su_` prefix) and its own small Redis client; notices between servers through Redis and a notice table, notices older than a day deleted hourly.
- Staff groups (`staff.groups`, entries `group:Label:#RRGGBB`) and `staff.operators`; LuckPerms read through the Forge mod or the Bukkit plugin on Mohist, including every member of a group.
- Editing rights: operators (level 2) and BSP-Core admins.
- `/serverutils status` (short form `/su status`): where records are kept, this server's name, LuckPerms, BSP-Core and the staff groups.
- The project: Forge 1.20.1 mod `bsp_server_utilities`, BSP-Core 1.4.0 as an optional dependency, the LuckPerms API for compiling, the GameTest setup with an empty test structure, and the language file generator.
