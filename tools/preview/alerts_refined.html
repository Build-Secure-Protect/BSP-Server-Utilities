Server alerts: the refined look

SU-167, D826 to D834: BK A (a plain-text letter) and BL A (a banner on every tab, coloured tiles and RECENT ALERTS on WORLDS). One email per outage and one when it is back (D830, D828); servers that go out within the same minute share an email. Server names are the network's; times, players and numbers are made up.

R1 · the alert email

Plain text, sent from the Google account made for alerts to the addresses in the panel's ALERT_EMAIL_TO variable. Times in UK time. Sent once per outage, about 80 seconds after the server was last heard (silent 20 s, then three checks 20 s apart).

FromBSP staff panelToownerBSP-Frostwarf is frozen
BSP-Frostwarf is frozen: it stopped sending at 14:02:15
(Friday 27 November, UK time), 1 minute 20 seconds before
this email. Its port still answers, so the game is stuck
but the server process is still running.

Last heard     14:02:15, 11 players online, 48.2 ms a tick
Checked        14:02:55, 14:03:15, 14:03:35: silent each time
Its port       192.168.1.27:25565 answered at 14:03:35

A frozen server does not stop on its own: restart it in
Pterodactyl (Console, Restart; Kill if it will not stop).

WORLDS on the panel:
https://staff.buildsecureprotect.com/#worlds

This is the only email for this outage. You get one more
when BSP-Frostwarf is back.

R2 · every kind of alert

The subject and the first paragraph for each kind; the rest of the letter is as R1 (last heard, the checks, the port, what to do, the link).

FROZENBSP-Frostwarf is frozenIts port still answers, so the game is stuck but the server process is still running.
CRASHEDBSP-Stormfall has crashedIts port is closed: the server crashed, or was stopped without saying so (a Kill in Pterodactyl). If Pterodactyl restarts it, you get the back email.
NO ANSWERBSP-Moongrove is not answeringIts address did not answer at all within 3 seconds: the server or the machine it runs on may be down, or the network between them.
NOT SENDINGBSP-Sanctuary is not sendingThe panel has no address for it, so it cannot tell frozen from crashed. (Fixed by the address in its snapshot, or in the panel's ALERT_SERVERS variable.)
NOT BACKBSP-Spawn is not back after its restartIt said it was stopping at 06:00:04 and has not sent anything in the 5 minutes since. Its port is closed (it is not running) / still answers (it is running but stuck starting or stopping).
SLOWBSP-Boulderbrook is very slowOnly when the panel's ALERT_SLOW_MSPT variable is set (off by default). Above 100 ms a tick (under 10 TPS) for 5 minutes running; back once it stays under for 2 minutes.
PANELThe staff panel cannot hear the game serversNo game server has been heard for 20 seconds, so the fault is most likely the panel's own Redis or database, not seven servers at once. Server alerts wait until it hears one again; one email, and one when it hears them again.

R3 · shared and back emails

Servers whose silences begin within a minute of each other share one email (the panel waits for the other's checks to finish, at most about a minute more). Back emails that fall due together share one too. A back email goes only after an alert email went.

R4 · the panel

A banner on every tab while an alert is open (red; blue while a planned restart is in its 5 minutes; gold while the panel is checking a server, on WORLDS only). The tiles say what happened. RECENT ALERTS under the grid: the last 7 days (30 kept), newest first. Owners also see the email line and SEND TEST EMAIL; everyone else sees the alerts only.
